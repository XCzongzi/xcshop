# Alpha r0

按 `xcshop-datapack` 测试数据包翻译的 Minecraft Java 26.3 模板，要求项目 `dataVersion = 0`。
当前套件需要 **xcshop-builder 0.1.3 或更新版本**：lore JSON 和函数文本分别通过原生 `jsonArrayTexts`、`splitLines` 迭代，避免逐字符模板循环耗尽执行预算。输出格式及游戏行为保持原有规则。

模板 ID：`89755dae-f798-440d-b3a9-342ee8a9070f`。

## 文件

- 模板：`templates/alpha-r0.xcshopT`
- 蓝图：`blueprints/alpha-r0/`
- 材料：`materials/alpha-r0-26.3/`，全部为根目录文件；材料正文不包含原型注释。

选择 Alpha r0 后正常构建即可；不会自动修改项目当前所选模板，也不会覆盖其它 Alpha 修订。

## 与测试包的对应

运行命名空间使用项目设置（`xcshop.json` 的 `namespace`），函数、进度及 load/tick 标签中的资源引用均随之生成；计分板和标记沿用原型。容器校验仅排除末影箱、大型箱子和大型陷阱箱；其它容器不受 27 格限制。

独立构建器也会校验容器 ID。目前仍不接受彩色潜影盒 ID，会在执行模板前报错；模板放行不改变构建器自身的这一限制。

保留原包的 `tick → detection → locate/shop`、掉落物检测与定位、标记实体、实例编号、容器刷新和矿车归还流程。`item_return` 复制并清空 0–26 格，不再访问 27–53 格。打开商店仍刷新该注册名下的全部商店实例。

`tick.mcfunction` 在玩家检测结束后清除带有 `minecraft:custom_data.xcshop.xcshop:1b` 标记的商品掉落物，每 tick 执行一次。

`_summon/<商店注册名>` 创建商店。UI 的 `openCommand` 写入 `opened/<商店注册名>` 的刷新之后；非空 `customName` 设置容器名称。占位商品由构建器逐槽位展开为正式商品，蓝图统一生成其物品、展示和操作，不再单独生成占位填充函数；需要使用支持此展开方式的构建器。在刷新商品前清空含候选商品的槽位，避免条件切换后残留上一页商品，最后运行原型的 modifier。

创建商店前先删除创建位置（对齐到方块整数坐标）的旧商店 marker，避免重复创建时叠加标记。每次打开商店时，在刷新之前检查当前维度中已加载的商店 marker，删除所在方块已不含商店注册数据（`components.minecraft:custom_data.xcshop.shop`）的标记；不在 tick 中执行这项检查。

手动执行 `/function <项目命名空间>:clear_marker`，检查所有维度中已加载、带有 `xcshop.shop` 标签的 `minecraft:marker`。若所在方块没有容器物品列表 `Items`、缺少 `components.minecraft:custom_data.xcshop.shop` 或 `id`，或容器的 `id` 与 marker 的 `__xcshop__` 分数不同（包括 marker 缺少分数），则删除该 marker。有效的空容器会保留；不修改容器及 marker 的实例编号。未加载区块中的 marker 需在加载后再次调用此函数；此函数不自动接入 tick 或打开商店流程。

普通商品及嵌套组汇总后的筛选由 Shop IR 的 `items[].filters[]` 提供，需要使用支持此字段的构建器。条件按外层嵌套组、内层嵌套组、商品自身的顺序同时检查；显示、拿取、掷出均使用全部条件。每层嵌套组绘制的槽位范围都会生效。

`load.mcfunction` 集中创建全部已注册商店配置引用的计分板：所有层级筛选、计分板代价（含仅筛选的代价）、布局输入器的筛选和结果。同名只声明一次，用户计分板采用 `dummy`，已有计分板不删除或重建。自定义指令和外部函数的文本内容不参与计分板名称收集。

拿取操作：`shop/<商店>/<槽位>/<商品>/trigger/<操作序号>.mcfunction`。

商品数量为 1（包括未填写数量而使用默认值 1）时，拿取操作使用数量筛选会产生模板警告，构建仍可继续。单个商品无法区分整组与部分取得，“不足整组”等筛选可能永远无法触发；请检查商品数量或改用无筛选。

掷出操作：`shop/<商店>/<槽位>/<商品>/trigger/<操作序号>/sell.mcfunction`。掷出路由在匹配掉落物后通过 `on origin` 切回玩家，随后检查代价并执行操作。单个掷出匹配数量 1，整组掷出匹配数量 2 及以上，沿用原型判断。

操作按数组顺序判断；先检查本操作的全部代价，再扣除并执行。不扣除 `type.filter` 代价，execute 条件只判断不扣除。指令原文直接写入；执行函数的每个非空行加上 `function` 前缀。

成功/失败提示开关各自同时控制对应文字和音效。“成功后返回”默认关闭，启用后只在当前操作成功时结束本商品的后续操作，失败继续。按原型，成功指代价检查通过并执行操作内容，不额外检查用户指令的返回值。

为落实成功后返回，操作末尾补充 `return 1`，失败提示函数末尾补充 `return fail`；关闭失败提示时直接 `return fail`。拿取数量复制到原型已声明的 `#items_per_slot`，防止代价检查覆盖 `#item_record` 后影响后续操作判断。

额外展示使用构建器计算的 lore JSON 列表，在生成时拆成原型的逐行 `append value` 命令，不增加运行时 storage 或其它展示中转流程。

## 布局输入器

不自动接入 tick、打开商店或交易流程。自行以玩家为执行者调用：

```mcfunction
function <项目命名空间>:input/<商店注册名>/<布局管理器id>
```

与原型一样，玩家的 `__xcshop__` 分数须已指向商店实例，原有商品定位流程会设置它。入口依次匹配所有实例编号相同的商店标记；`match` 先设置默认值，再按连接顺序匹配，后匹配成功的值覆盖之前的值。

只检查嵌套组绘制的槽位；空槽位要求为空，非空槽位允许任一候选物品。多个候选使用同一条命令串联 `unless items`，与原型槽位 23 的“经验瓶或石头”一致。候选物品仅匹配物品，不使用末尾的生成数量。

布局匹配不执行计分板筛选。构建器将筛选忽略并警告到原 UI 的对应 `filter`；同一 UI/槽位同时作为普通商店或普通嵌套商品使用时，普通用途仍检查筛选是否合法并正常使用筛选。

## 验证

使用支持 `@namespace` 的真实构建器运行 `node tests/AlphaNamespaceTests.cjs [构建器路径]`，检查默认、自定义、含点和连字符及 `minecraft` 命名空间下的输出目录、函数引用、进度奖励和 load/tick 标签；测试仅写临时目录。

运行 `node tests/AlphaContainerTests.cjs [构建器路径]`，检查构建器 0.1.2 可识别的 17 种容器：仅末影箱、大型箱子和大型陷阱箱构建报错，其它容器按各自布局生成最后一个槽位的商品，并使用商店注册数据清理失效标记。此检查验证构建输出，不替代游戏内验证。

本仓库的 `tests/test_pack_kits.py` 检查套件 ZIP 的输入范围、内容一致性和可重复打包；编辑器构建套件测试检查模板及依赖的导入。实际生成数据包需要另行获取兼容的独立构建器，并检查生成结构、交易条件与扣费顺序、操作开关及布局匹配。源码检查不能代替游戏内验证。
