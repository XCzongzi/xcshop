# 从源码构建编辑器

本页说明现有配置的使用方法，不代表下列命令已在本次文档整理中重新执行。发行前需按[分发与开源准备](分发与开源.md)从完整源码材料重新验证。

## 环境

| 项目 | 要求或现有开发配置 |
| --- | --- |
| CMake | 项目声明最低 3.16；还需满足所选 Qt 套件的要求，本机安装为 3.30 |
| 语言 | C++17 |
| Qt | 配置声明最低 6.8；现有构建使用社区版 6.11.2 |
| Windows 编译套件 | 现有开发配置为 x64、MinGW 13.1.0、Ninja |
| 必需模块 | Quick、QuickControls2、Network、Concurrent，及其 Core/Gui/Qml 等依赖 |
| QML 运行模块 | Controls、Templates、Layouts、Dialogs、Effects、Qt5Compat.GraphicalEffects、Qt.labs.folderlistmodel；Controls.impl 亦有使用 |
| 测试 | 启用 CMake 测试时还需要 Qt Test；JS 语法测试单独使用 Node.js |

Qt 头文件、库、插件、QML 模块和编译器需来自匹配的安装套件。编辑器现有 MinGW 配置与构建器的 MSVC 构建不必相同，两者通过独立进程通信。使用 MSVC 编译编辑器时，应另选匹配的 MSVC Qt 套件并验证，不能把 MinGW Qt 库直接用于 MSVC 链接。

## 先准备构建材料

当前 `.gitignore` 忽略了整个 `assets/minecraft/` 和 `kits/`。`gui.qrc`、`container.qrc` 会直接引用其中的八张 GUI 图片，CMake 也会复制和安装 `kits/`。请按[资源清单](release/资源清单.md)取得对应版本的文件，保持原相对路径。

源码公开前，发布者需为这些文件确定实际可用的获取方式，并记录版本、校验值及适用的权利说明。本文档没有虚构一个尚未发布的下载地址。若资源被合法地分开提供，必须把它们纳入对应源码和可重建材料的安排；不能把缺失的必要构建输入当成“只有作者电脑能提供”的隐含条件。

作者已确认 GUI 图片来自游戏 JAR，套件为原创与 AI 辅助制作，详见[素材与套件来源](release/素材与套件来源.md)。源码仓库为 [XCzongzi/xcshop](https://github.com/XCzongzi/xcshop)，正式下载页尚未准备好；本次没有把未跟踪的资源或套件上传到该仓库。

`builder/xcshop-builder-0.1.0.exe` 不参与编辑器自身的编译。要使用实际的数据包构建功能，需取得另行发布的兼容构建器，并在设置中选择可执行文件；其独立许可不由编辑器的 GPL 自动替代。构建套件及其依赖也应准备好。

## 配置开发环境

在已配置好 Qt、CMake、Ninja 和对应编译器的 PowerShell 中操作。以下路径是示例，替换成实际安装位置；不要照抄作者电脑的绝对路径。

```powershell
$qtKit = 'C:\Qt\6.11.2\mingw_64'
Get-Command cmake, ninja, g++
```

如果命令不存在，先在终端的 PATH 中配置 CMake、Ninja、该 Qt 套件的 `bin` 及匹配的 MinGW `bin`，或使用 Qt 提供的构建环境。下面的命令从仓库根目录运行。

## 编译 Release 编辑器

```powershell
cmake -S . -B out/release -G Ninja "-DCMAKE_PREFIX_PATH=$qtKit" -DCMAKE_BUILD_TYPE=Release -DXCSHOP_BUILD_TESTS=OFF
cmake --build out/release --target appxcshop
```

Ninja 单配置构建的可执行文件为 `out/release/appxcshop.exe`。更换 Qt、编译器或架构时使用新的构建目录，不混用已有缓存。

开发机运行可能依赖 Qt 的开发环境。可执行文件能在开发机启动，并不代表它已经完成部署；给其他人使用前仍需收集 Qt/QML 插件和运行库，见[分发文档](分发与开源.md)。

## 编译和运行已有测试

```powershell
cmake -S . -B out/tests -G Ninja "-DCMAKE_PREFIX_PATH=$qtKit" -DCMAKE_BUILD_TYPE=Debug -DXCSHOP_BUILD_TESTS=ON
cmake --build out/tests
ctest --test-dir out/tests --output-on-failure
node tests/ItemSyntaxTests.cjs
```

CTest 已登记后端、资源导入及界面检查；部分 Windows 窗口检查使用真实平台插件和 D3D11，需要可用的桌面图形环境。软件渲染检查不能替代所有 GPU 效果验证。界面检查可能生成截图和临时数据，不应加入源码包。

`appxcshop --ui-smoke` 是现有文档中的额外集成入口，会使用真实构建器和套件；不要把 `tests/BuilderProtocolFixture.cpp` 的协议测试替身当成实际构建器。真实 Minecraft 导入检查会按入口涉及游戏文件、Java 和可能的下载，只在准备好独立测试目录后运行，参阅[导入文档](Minecraft物品资源导入.md)。

## 接口与兼容性

默认构建器名称为 `xcshop-builder-0.1.0.exe`。编辑器调用 `--version` 获取版本信息，构建时使用 `--project <项目目录> --kits <套件目录>`，解析 `XCSHOP_BUILD_RESULT ` 前缀的 JSON 结果，当前结果协议版本为 `0`。

编辑器项目数据版本、结果协议版本、构建器版本、Minecraft 游戏版本是不同概念。具体字段、错误处理和套件目录结构见[构建器接入](构建器接入.md)。
