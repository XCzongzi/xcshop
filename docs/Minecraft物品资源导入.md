# Minecraft 物品资源导入

设置 → 物品信息 → 导入物品资源，导入 Java 版 1.13 起正式版及后续测试版的基础物品。游戏文件可以来自原版安装或整合包。

- **本地游戏（默认）**：选择客户端 JAR、游戏目录或整合包版本目录，自动识别基础 Minecraft 版本，不显示版本选择器。优先读取 JAR 内的 `version.json`，不把整合包名称当成版本；1.13 等旧版本也可从 `clientVersion` 或基础版本 JSON 识别。启动 JSON 使用 Fabric、Forge 等入口不会导致原版游戏 JAR 被拒绝。支持合并后的版本配置、`inheritsFrom`/`jar` 继承引用及 Prism/MultiMC 的 `mmc-pack.json` 版本引用，继承引用可定位上级目录中的基础游戏文件。游戏根目录有多个基础版本时自动选取最新版本并提示；也可直接选择目标文件。
- **在线下载**：只在这个入口选择版本，从 Mojang 官方获取客户端和所需依赖。版本选择器默认隐藏测试版，可手动显示；已有文件直接复用。
- **高级选项（默认折叠）**：Java 路径、依赖目录、允许联网补齐缺失文件、重新生成已有图标。通常保持默认即可。切换入口不会把在线选择的版本套用到本地文件，也不会在在线导入时复用另一个本地客户端。

Java 会从游戏/启动器附近的 `runtime`、`java`、`jre`、`runtimes`、PATH、JAVA_HOME 和常见安装目录查找，优先使用版本元数据要求的主版本。若更高版本 Java 不能运行旧版生成器，可在高级选项指定对应运行时。程序不下载 Java，也不修改系统 Java。

“当前资源”卡片右上角的“切换版本”用于重新启用已经导入完成的本地版本，支持搜索并标记当前版本。同一游戏版本有多次导入记录时合并显示，优先当前使用的资源，其次当前渲染器生成的最新记录；未完成或目录信息损坏的记录不显示。切换只原子更新资源指针，不下载文件、不运行 Java，也不重新生成图标；物品列表和编辑器图标随之刷新，自定义物品继续保留。导入期间不能切换，资源被移除或其它进程正在导入时切换失败并保留原指针。

## 数据来源与流程

1. 本地入口先识别文件、按客户端 SHA-1 查询完成的资源包。命中后直接启用，无需 Java、依赖或在线版本列表。在线入口读取 `https://piston-meta.mojang.com/mc/game/version_manifest_v2.json` 并校验版本元数据。
2. 未命中资源包时，本地优先读取同目录版本 JSON 和已有元数据缓存，按其中的客户端 SHA-1 校验 JAR；信息缺失且允许联网时才获取官方元数据。在线入口下载并校验客户端。
3. 默认运行**客户端**的 `net.minecraft.data.Main --reports`，不运行整合包的模组加载器入口。读取合并配置时使用游戏本体的校验信息，剥离加载器入口与非官方来源的加载器依赖，不读取 `mods` 内容。按版本 JSON 的操作系统规则选择依赖，只加载对应版本的文件，依次查找指定依赖目录、游戏/启动器上级共享 `libraries`、常见游戏目录及应用缓存。所有依赖均校验 SHA-1；缺少或损坏时仅在允许联网的情况下从官方 HTTPS 地址补齐。下载的相同依赖按哈希共享缓存，不写入或覆盖用户游戏目录。
4. 从注册报告获取完整物品 ID。1.13 的旧式 `items.json` 与新版 `registries.json` 分别处理；1.20.5 起的默认组件，以及 26.1 起按物品输出的默认组件会合并进清单。
5. 使用客户端资源渲染默认物品状态。渲染失败仍保留物品条目，分别标记默认图标、近似预览、缺少图标。
6. 在暂存目录完成整包写入后，原子更新 `active.json`，切换整个版本。

完整列表指基础 Minecraft 版本注册的物品类型，包含空气注册项（设置列表隐藏空气）。整合包内的游戏 JAR 通常仍是原版，可以直接复用；导入结果不包含模组新增物品，也不应用整合包资源包覆盖。不会枚举所有药水效果、染色、附魔、玩家皮肤等物品堆叠变体。基岩版和修改了游戏本体、无法通过原版 SHA-1 校验的 JAR 不在此流程支持范围。

不会自动下载服务端。客户端生成失败且该版本提供服务端时，高级选项才出现手动备用按钮，并显示预计下载大小或已缓存状态。点击后才使用服务端生成，仍然需要 Java。支持旧式单 JAR 的 classpath 启动和新版服务端的 `bundlerMainClass` 启动。

## 存储与失败处理

应用目录的 `assets/minecraft/items/` 包含：

| 路径 | 用途 |
| --- | --- |
| `active.json` | 当前生效的完整资源包指针 |
| `packs/<客户端哈希>-r<渲染器版本>-<唯一标识>/catalog.json` | 版本、来源、默认组件、渲染状态与完整物品清单 |
| `packs/.../assets/minecraft/` | 对应版本的图标 |
| `cache/` | 官方元数据、校验后的下载、生成的报告和资源包索引 |
| `cache/libraries/<SHA-1>.jar` | 跨游戏版本复用的已下载依赖 |
| `cache/reports/<客户端哈希>-client/` | 客户端生成的完整物品报告和默认组件；重绘图标时可复用 |
| `custom-items.json`、`assets/<命名空间>/` | 独立保存的自定义物品与图标 |
| `import-settings.json` | 上次填写的导入选项 |

切换页面不终止导入；取消会停止下载或数据生成器。清单生成、文件校验、解压或渲染流程失败时，不修改当前资源指针。已生成资源包可直接切换；“重新生成已有图标”用于修复图标或应用新版渲染器。内置物品列表仅从当前资源包的 `catalog.json` 读取，自定义物品由 `custom-items.json` 管理。

完整本地安装具备客户端、版本 JSON、适用依赖及 Java 时，首次导入也可以离线完成，不依赖在线版本列表。关闭高级选项中的“允许联网补齐缺失文件”后，导入流程不会发起下载；缺少或损坏依赖时列出文件路径，不自动切换服务端。只提供独立 JAR 时，如果既没有对应版本 JSON，也没有元数据缓存，需要先联网补齐信息。已完成的资源包可以直接离线切换；已生成的报告可复用，不必再次运行 Java。刷新在线版本列表失败时使用已有缓存并显示提示。

不同启动器可能把版本 JSON、依赖库和 Java 放在不同位置。自动查找覆盖常见结构，不承诺识别每个启动器；特殊目录可在高级选项指定。随软件不分发所有历史依赖，也不分发游戏 JAR。默认错误提示只显示摘要，完整错误和缺失文件列表放在高级选项。

## 渲染兼容范围

渲染器支持旧式模型继承、默认状态覆盖选择、多层生成贴图、动画默认帧、图集别名/裁切/调色板，以及新版条件、选择、范围和组合模型。特殊物品使用独立的本地几何预览。

近似预览会在条目中说明原因，例如旧版刷怪蛋的代码内着色、环境相关指南针状态、特殊模型几何、子模型变换或组合模型合成。未知未来模型类型保留物品条目并显示缺失原因。此流程保证已识别报告中的物品清单完整，不承诺所有历史或未来客户端的图标都与游戏逐像素一致。

新增版本若沿用已支持的报告与资源格式，可直接导入；更改生成器入口或报告结构时需要更新 `MinecraftGameData.cpp`，新增显示格式则更新 `MinecraftItemRenderer.cpp`。无法识别报告时停止导入，避免将资源目录扫描结果误当完整注册表。

## 验证

配置 `XCSHOP_BUILD_TESTS=ON` 后运行 CTest。`minecraft_import_tests` 覆盖报告解析、版本排序、路径校验、本地自动识别、整合包合并配置、继承配置和 Prism 版本引用、继承循环、无在线列表的本地导入、依赖缺失/损坏/路径检查、缓存启用、取消与失败隔离，以及渲染逻辑。`minecraft_items_ui_smoke` 验证两个入口的显示与参数隔离、高级选项默认折叠、离线开关、物品筛选、自定义图标独立保存和页面重建，并输出默认、窄窗口、高级选项和在线版本选择截图。

可选的真实官方资源集成检查：

```powershell
minecraft_import_tests.exe --import 1.13 <独立测试资源目录> <java.exe路径>
minecraft_import_tests.exe --import 1.21.4 <独立测试资源目录> <java.exe路径>
minecraft_import_tests.exe --import 26.3 <独立测试资源目录> <java.exe路径> --rebuild
minecraft_import_tests.exe --import ignored <独立测试资源目录> <java.exe路径> --local <客户端JAR或游戏目录> --libraries <libraries目录> --offline
minecraft_import_tests.exe --import 1.21.4 <独立测试资源目录> <java.exe路径> --server
```

默认集成检查按需下载客户端和依赖，并运行客户端数据生成器。`--local` 自动识别本地版本，忽略位置参数中的在线版本；`--offline` 禁止联网；`--server` 显式使用服务端备用方式。使用独立输出目录，避免切换日常使用的资源。

原服务端生成流程使用真实官方文件验证的结果如下。物品数包含空气；空气不生成图标。

| 版本 | 注册物品 | 默认图标 | 近似预览 | 缺少图标 |
| --- | ---: | ---: | ---: | ---: |
| 1.13 | 785 | 667 | 117 | 0 |
| 1.19.4 | 1228 | 1078 | 149 | 0 |
| 1.20.5 | 1330 | 1177 | 152 | 0 |
| 1.21.4 | 1385 | 1291 | 93 | 0 |
| 26.3 | 1658 | 1542 | 115 | 0 |

客户端优先流程也已使用同一组五个版本逐一验证，注册物品数和渲染统计与上表一致，验证期间没有下载服务端。26.3 另以全新输出目录、关闭联网、不指定 Java、复用本地依赖的方式首次导入通过，输出目录没有在线版本列表或游戏下载缓存。自动化检查还验证了没有在线版本列表的本地首次导入，以及没有 Java/依赖时激活已有缓存。

整合包来源另使用 PCL 安装的 Fabulously Optimized 26.3 版本目录验证：直接选择该目录，关闭联网，不手动指定 Java 或依赖位置，在全新输出目录导入成功。生成 1658 项基础物品、1542 个默认图标、115 个近似图标、0 项缺少图标，与对应原版一致；没有启动模组加载器或下载服务端。

这些检查覆盖主要格式边界，并非逐一验证每个历史补丁版或测试版。未来版本仍需沿用已支持的生成器入口和数据格式；不保证无需更新就能支持所有未来格式。
