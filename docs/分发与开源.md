## 2. 编译并部署 Windows Release

在 Qt、编译器、CMake、Ninja 环境配置正确、必要资源和套件到位后，从仓库根目录运行。变量中的 Qt 路径是示例。

```powershell
$qtKit = 'C:\Qt\6.11.2\mingw_64'
cmake -S . -B out/release -G Ninja "-DCMAKE_PREFIX_PATH=$qtKit" -DCMAKE_BUILD_TYPE=Release -DXCSHOP_BUILD_TESTS=OFF
cmake --build out/release --target appxcshop
cmake --install out/release --prefix out/package/xcshop-0.1.0-win64
```

现有 CMake 默认把程序和套件安装到 `bin/`。用与构建匹配的 `windeployqt` 部署，并保留实际输出以生成清单：

```powershell
$packageDir = Join-Path (Get-Location) 'out/package/xcshop-0.1.0-win64'
$programDir = Join-Path $packageDir 'bin'
& "$qtKit/bin/windeployqt.exe" --release --qmldir (Join-Path (Get-Location) 'qml') --json (Join-Path $programDir 'appxcshop.exe') |
    Set-Content -Encoding UTF8 (Join-Path $packageDir 'qt-deployment.json')
```

每个阶段检查命令退出码，任一步失败都先处理，不把部分输出当成成功发布包。版本号随实际发布替换；使用新的打包目录，避免旧文件混入。这些命令是准备说明，本次没有执行安装或创建该成品目录。

`windeployqt` 主要收集 Qt/QML 和运行依赖，不会替你制作完整许可证、Qt 源码下载安排、独立构建器或 Minecraft 预装资源。结合实际功能检查 Windows 平台插件、Basic Controls 样式、图形效果、FolderListModel、Dialogs、SVG 图像支持和联网导入所需依赖；不要把整个 Qt 安装目录塞入发布包。

## 5. 提供真正可用的对应源码

采用 GPLv3 第 6 条允许的方式提供与二进制对应的完整源码。本项目优先采用在同一发布下载处提供源码归档的方式，避免写一个没有落实渠道、期限及履行能力的书面提供承诺。

每次发布应实际填写并验证：

- 编辑器源码提交/标签、完整源码归档、必要资源和构建输入的获取安排及校验值。
- Qt 精确版本与配置，对应模块和第三方代码的源码、所做修改/补丁及必要构建材料，实际可访问的源码归档与校验值。
- 其他随附库按其许可需要的源码或说明。

Qt 源码不一定要塞进每个可执行文件压缩包，但它的获取安排需要真实、有效并符合所选许可。按 Qt 官方说明，不能仅链接 Qt 官网提供的源码而把自身义务视为已完成。发布者应保存并提供与实际分发库相匹配的材料；更新或撤下二进制时，也需按实际采用的分发条款处理源码可用性。

本仓库已经附上 GPL/LGPL 文本及当前 Qt 许可参考集合，未附完整 Qt 源码，也未虚构可下载地址。请在[发布说明模板](release/发布说明模板.md)中填写实际渠道。
