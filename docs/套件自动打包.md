# 套件自动打包

`.github/workflows/pack-kits.yml` 会把默认分支（当前为 `main`）中受 Git 跟踪的 `kits/` 文件打包成根目录的 `kits.zip`，并以 `github-actions[bot]` 的身份提交回同一分支。不需要构建 Qt 软件，也不创建软件 Release。

## 编辑器获取与导入

在 **设置 → 构建套件 → 获取套件** 点击“下载并导入”，编辑器从 `https://xczongzi.net/projects/xcshop/downloads/kits.zip` 获取完整套件包，解压、校验后合并到当前已应用的套件目录。也可选择“导入 ZIP…”或“导入文件夹…”。ZIP 支持顶层 `kits/`，也支持直接包含 `templates/`、`blueprints/`、`materials/`；文件夹导入应选择内含 `templates/` 的 kits 根目录。

获取在后台执行，可取消；下载或校验失败不会修改目标目录，导入失败或取消时会撤销本次新增文件。导入沿用模板 UUID、依赖与目录边界检查，相同内容的文件直接复用，同名但不同内容的文件不会被覆盖。本地编辑过的套件与新版冲突时，请先备份并整理提示中的冲突文件，再重试。导入不会改动项目的模板选择或新项目默认模板。

压缩包限制为 128 MiB、最多 10,000 个条目，解压后总计不超过 256 MiB，单文件不超过 32 MiB。损坏文件、重复路径、目录穿越及符号链接会被拒绝。ZIP 读取封装在 `src/BuildKitArchive.cpp` 中，使用 zlib 解压并验证 CRC；支持 UTF-8 文件名、普通单卷 ZIP 的 store / deflate 压缩，不支持加密、ZIP64 或旧式文件名编码，无需外部解压程序。

## 触发方式

- 向默认分支推送 `kits/**`、打包脚本、打包测试或工作流本身的改动时自动执行。
- 也可以进入 GitHub 的 **Actions → Pack kits → Run workflow**，选择默认分支手动执行。
- 其他分支不发布压缩包；默认分支名称从仓库配置读取。

压缩包保留顶层 `kits/`，解压后得到 `kits/templates/`、`kits/blueprints/`、`kits/materials/` 和套件说明文件。只包含 Git 跟踪的文件，不包含本地忽略或未跟踪的其他套件；新套件需要先修改忽略规则并加入 Git。

条目按路径排序，使用固定时间戳和权限。文件内容没有改变时，重复运行不会仅因文件时间变化而产生新的压缩包提交。工作流只提交 `kits.zip`，并在并发推送冲突时重新拉取最新代码、重新打包后重试，不强制推送。

## 下载地址与 Worker

仓库公开、文件已推送或工作流第一次成功运行后，当前 `main` 分支对应的原始下载地址为：

```text
https://raw.githubusercontent.com/XCzongzi/xcshop/main/kits.zip
```

Worker 中的下载映射应为：

```text
https://xczongzi.net/projects/xcshop/downloads/kits.zip
  → https://raw.githubusercontent.com/XCzongzi/xcshop/main/kits.zip
```

如果现有 Worker 已能把这个下载路径映射到仓库根目录的同名单文件，就可直接复用。Worker 代码不在本仓库中，这个工作流不会自行创建域名路由；如果 Worker 目前把路径原样拼到 GitHub Raw 后面，需要添加上述映射。默认分支改名后，也要同步修改 Worker 上游地址。

第一次使用时，把工作流、脚本、测试和套件源文件一同推送到 GitHub，并在 Actions 页面确认运行成功。工作流已声明 `contents: write`，使用内置 `GITHUB_TOKEN`，不需要额外配置个人令牌。若仓库或组织策略限制写入，或者分支保护禁止机器人直接提交，需要调整对应规则。工作流生成的提交不会再次触发自己的推送流程。

工作流提交后，本地再次修改前先拉取默认分支，避免本地推送落后于机器人生成的提交。

## 本地验证

在项目根目录使用 Python 3.10 或更高版本运行（仅使用标准库，需要 Git）：

```powershell
python -B -m unittest discover -s tests -p "test_pack_kits.py" -v
python tools/pack_kits.py
```

默认生成根目录的 `kits.zip`，也可用 `--output out/kits.zip` 指定输出文件。脚本读取受 Git 跟踪文件的当前工作区内容，因此本地未提交的修改也会进入本地生成的压缩包。

GitHub Actions 对应规则见[工作流触发](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)和 [checkout 的机器人提交示例](https://github.com/actions/checkout#push-a-commit-using-the-built-in-token)。
