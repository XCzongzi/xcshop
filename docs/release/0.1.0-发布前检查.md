# xcshop 0.1.0 发布前检查

检查日期：2026-11-09（Asia/Shanghai）。目标：编辑器 **0.1.0**，发布日期 **2026-11-09**，独立构建器 **0.1.3**。

**结论：当前发布输入尚不满足正式发布条件。** 仓库内构建器无法构建当前内置套件，套件 ZIP 与源码不同步，发布输入校验失败；完整 CTest 为 27/29，通过干净源码生成 Release 的验证也未完成。

基线提交：`af90638c7966f25f47a5c15d45116d6da37e70b3`。开始检查时工作区干净。本次仅新增检查报告，未修改业务代码、套件、版本信息或构建器二进制，未提交或发布。

## 必须先处理的问题

### 1. 仓库内构建器 0.1.3 不能处理当前套件的数据包版本宏

- 文件：`builder/xcshop-builder-0.1.3.exe`，757248 字节，文件修改日期为 2026-11-08。
- `--version` 正常返回 `builderVersion: 0.1.3`、结果协议 `0`、项目数据版本上限 `0`；版本查询成功并不代表功能兼容。
- 当前 [pack.xcontent](../../kits/materials/alpha-r0-26.3/pack.xcontent) 第 8、9 行使用 `@dataPackVersion.major/minor`。真实构建在第 8 行中止，提示“根作用域只能读取 @namespace、已声明的变量或迭代根数组”。结果为 `buildSucceeded: false`、`outputWritten: false`。
- 数量警告、容器和命名空间三组真实构建测试，使用仓库内该二进制均失败。

仓库内二进制 SHA-256：

```text
9f905b8c9b94608a36631ea25ec32a094d14996c497b6488589ef1743277ec9d
```

本机相邻构建器项目另有较新候选文件 `D:/Projects/Code/cpp/xcshop-builder/x64/Release/xcshop-builder.exe`，760832 字节，文件修改日期为 2026-11-09，同样声明版本 0.1.3。用该候选执行相同测试：数量警告 8 例、容器 17 例（含 3 例预期拒绝）、命名空间 4 例，合计 29 例全部符合预期。

该候选 SHA-256：

```text
f213ade405123b8894a8c5e2d86892c38e0845d228e67454b0c9a5c474304899
```

处理：确定并同步真正要随包发布的 0.1.3 二进制，记录来源和校验值，再用最终路径重跑三组测试。本次未替换仓库内文件。候选的这些测试通过，不代表已经完成其运行库、最终部署和 Minecraft 游戏内验证。

### 2. kits.zip 与当前套件源码不一致

根目录 `kits.zip` 包含 73 个文件，文件列表与 Git 跟踪的套件一致，ZIP CRC 检查通过，但以下 4 个文件的解压内容与当前源码不同：

```text
kits/alpha-r0-README.md
kits/materials/alpha-r0-26.3/pack.xcontent
kits/materials/alpha-r0-26.3/read_cursor.xcontent
kits/templates/alpha-r0.xcshopT
```

当前 ZIP SHA-256：`c9c9ac93697ac33e8bb6193429c05a62e1336b8949cd9f8896095a48b5ebd21a`。

处理：在确定最终构建器及套件后，使用 `python tools/pack_kits.py` 重新生成并逐项验证，确保下载入口所用 ZIP 与随包套件一致。本次仅在忽略的检查目录生成了对照 ZIP，没有覆盖根目录文件。

另发现 `build/kits/materials/alpha-r0-26.3/read_cursor.xcontent` 与源码不同。[SeedBuildKits.cmake](../../tools/SeedBuildKits.cmake) 有意保留已存在的套件文件；再次编译不会覆盖它。正式打包应从全新目录安装套件，不能复制日常 `build/kits` 后假定它是最新版。

### 3. 发布输入校验失败

运行 `node tools/check_publish_inputs.cjs`，退出码为 1：

```text

3992 !== 3986
```

[资源清单](资源清单.md) 对该模板记录的大小和 SHA-256 已过期。逐项比对所有已记录资源后，仅发现这一项不匹配。

| 项目 | 清单记录 | 当前文件 |
| --- | --- | --- |
| 字节数 | 3986 | 3992 |
| SHA-256 | `6264d530ed37dbf2e0fe8b7eae4f50a2a91bf0abc0e1f219f4613d5f83f695a3` | `cbd33ab29ec3b3a78a8a827533e0752f999c94f2d18df024094237b13a26aaef` |

处理：确定最终模板后更新清单并重跑发布输入脚本。本次该脚本在大小检查处即中止，不能把其后续文档链接、输入范围等检查记为通过。

### 4. 两项界面测试失败

完整命令：`ctest --test-dir build --output-on-failure`，总用时 262.15 秒，27/29 通过，退出码 8。

| 测试 | 实际失败 | 处理建议 |
| --- | --- | --- |
| `light_theme_ui_smoke` | `cloud: placeholder contrast 3.77 < 4.5` | 核对 [Colors.qml](../../qml/Colors.qml) 的浅色提示文字处理和 [XCTextField.qml](../../qml/components/base/XCTextField.qml) 的 0.78 透明度，修正后继续执行完整主题检查 |
| `page_transitions_ui_smoke` | `element failed to load`，首个 UI 元素被当前格式校验拒绝 | [测试文件](../../tests/PageTransitionsUiSmoke.qml) 第 102 行只为 Item、Display 使用完整默认结构，UI 和 Cost 从空对象开始；先补齐当前格式测试数据，再验证页面切换 |

页面切换失败可定位到测试数据：UI 文件仅有 `smokeTag`，不满足 [PageOnUI.qml](../../qml/pages/PageOnUI.qml) 第 1043 行起要求的 `containerType`、`slots`、`nestedGroups`。这次失败尚不能证明真实有效项目的页面切换有缺陷，也不能将该测试计为通过。浅色主题测试在第一项对比度断言处退出，其后主题与场景没有全部得到验证。

### 5. 发布时间与要求不一致

[PageOnAbout.qml](../../qml/pages/PageOnAbout.qml) 第 26 行仍为 `2026-11-08`，应按本次目标改为 `2026-11-09` 后重新构建。

[CMakeLists.txt](../../CMakeLists.txt) 的项目版本为 `0.1.0`，编译定义 `XCSHOP_VERSION`、`Qt.application.version` 和关于页版本展示的来源一致；[BuildManager.cpp](../../src/BuildManager.cpp) 的默认构建器路径为 `builder/xcshop-builder-0.1.3.exe`，这两项与目标一致。

### 6. 干净源码 Release 构建未通过

从基线提交用 `git archive` 导出源码，在 `out/preflight-0.1.0-20261109/source-utf8` 解包，以 Qt 6.11.2 MinGW x64、C++17、Release、`XCSHOP_BUILD_TESTS=OFF`、默认 `-O3 -DNDEBUG` 配置。CMake 配置及生成成功，编译在生成资源文件 `qrc_gui.cpp` 处因内存不足失败。

- 生成的 `qrc_gui.cpp` 为 125872934 字节，约 120 MiB。
- 并行度 4 时：`cc1plus.exe: out of memory allocating 2147487743 bytes`。
- 改用并行度 1 重试，仍在相同编译单元报内存不足。

处理：为资源编译降低内存需求，或在资源充足的构建环境重试，取得本次源码的实际 Release 构建记录。这是本机构建资源限制的实测结果，不据此断言所有机器都不能编译。未修改优化参数或源码来绕过失败，也未把旧 Release EXE 当成本次新构建。

补充尝试了已有 `out/release` 的增量构建，但其 QML 导入扫描长时间未完成，已终止本次启动的扫描进程；该尝试不计为构建通过。正式构建优先使用独立、干净的源码根目录，避免扫描日常源码目录中的大量历史验证副本。

## 其他发布信息与交付缺项

- 模板头的明确支持版本为 `"26.1.2"...`，而 [Alpha r0 说明](../../kits/alpha-r0-README.md) 仍将其描述为 Java 26.3 模板。真实测试使用 26.3 时产生“并未被明确支持”的版本警告；应明确本次支持范围并与模板说明保持一致。数据包版本映射正确不等于指令与模板逻辑已经通过游戏内兼容验证。
- [发布说明模板](发布说明模板.md) 尚不是本次填好的 Release 记录。本次没有发现可作为最终交付物的 0.1.0 成品包；既有 0.0.2 成品不计入本次验证。
- `builder/`、`kits/` 未发现各自独立的许可文件；`licenses/xcshop-builder-permission.txt` 是编辑器的构建器互操作额外许可。应按现有[分发文档](../分发与开源.md)补齐所要求的构建器单独说明、套件许可安排和实际运行库记录。本报告仅记录交付材料现状。
- 对应编辑器源码、实际部署 Qt 组件及其配套材料的下载安排，需填入本次发布记录并验证；本次未检查公网下载端点，不将其记为已经可用。
- 没有对最终包进行无开发环境 Windows 启动、中文/空格路径、离线预装图标、游戏内运行和最终压缩包校验；干净 Release 构建失败后未继续将旧 EXE 部署为本次成品。
- 现有分发文档中的 17/18 测试数字和 70 个套件文件为历史记录；本次实际是 27/29 CTest、73 个套件文件。
