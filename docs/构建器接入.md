# 构建套件与构建器

## 设置

“构建套件”管理一个 `kits` 根目录，其 `templates/` 下递归查找 `.xcshopT`。
模板是选择、默认项和项目引用的核心对象；详情中显示它使用的蓝图、材料包、介绍、数据版本及游戏版本。
项目使用模板头的 UUID（`templateId`），不再使用旧的数字 `template`。
本编辑器当前支持 `dataVersion: 0`（Item 操作组）。内置套件仅保留 Alpha r0，与该数据版本匹配。本次为发布前重新编号，不回退数据结构，不迁移旧格式项目。

编辑器不转换旧的代价类型索引、槽位数组、数字模板标识或空白 UI 文件。无法读取的元素显示错误并保留文件原文；设置仅使用当前的颜色字符串和背景模式。Minecraft 游戏版本支持独立保留，包括旧版物品语法、注册表和模型导入。

操作名称初始为空，允许不填写。Display 的“操作组成员 → 启用”控制整个操作组成员层：关闭时不显示操作名称、项头、项中、项尾及名称样式，也不校验这些未启用文本的 JSON；保留编辑值。代价名称与数量的样式仅在“代价组成员”中分别设置，不再提供重复的“代价文本”样式编辑。
“框架”始终包住整个文本，头尾只应用一次；其中“分隔文本”与“代价分隔”始终分别控制操作之间和同一操作内的分隔，不受操作组成员开关影响。
展示工作区宽屏为三列：预览占左两列，框架在右列；操作组成员、代价组成员位于预览下方并保持等高，提示信息位于框架下方。窄屏顺序排列。
“启用”位于操作组成员右上角，只改变展示计算，不折叠或禁用编辑内容。
展示文本使用富文本编辑，不显示原始 JSON。页面内保持原输入框的尺寸和展开、收起按钮，仅提供基本输入；完整颜色和样式工具栏在弹窗中提供，可设置后续输入或选中文字的颜色、粗体、斜体、下划线、删除线及混淆样式。颜色左对齐，样式及撤销操作右对齐，空间不足时换行。游戏预设显示颜色名（如 red），自定义颜色显示 RGB 色值；输入色值后可通过加号添加预设，右键自定义色块可载入、替换、排序或删除，预设保存在设置中。Enter 直接换行，弹窗支持 Ctrl+Enter 应用。页面内编辑即时保存，弹窗草稿仅在应用时写回，取消会丢弃草稿。内部使用 Minecraft 文本组件字符串，普通文本也是当前接口支持的输入；动态文本组件暂以只读方式保留。新建格式不预填文本。卡片沿用原触发规则的顶栏、右上角编号与图形删除按钮。
添加卡片展开 220ms；删除先右滑 200ms，再补位 120ms。动画期间仅拦截输入，不切换按钮禁用色。可调编辑框只由外层播放高度动画，父卡片直接跟随实际高度，不叠加缓动。

导入时选择另一个完整的 `kits` 根目录，目录内的相对路径会被保留。
相同内容的同名文件复用，不同内容的同名文件拒绝覆盖，重复 ID 拒绝导入。
移除模板仅将 `.xcshopT` 文件移入回收站，保留可共享的蓝图和材料；依赖文件可从详情定位。
软件构建时仅补充缺失的内置套件文件，不覆盖已有文件。
在线仓库尚未接入，入口仅在设置中显示，不请求旧仓库。

“构建器”管理可执行文件路径。默认使用程序目录下的：

`builder/xcshop-builder-0.1.0.exe`

应用路径或恢复默认路径时自动获取并校验版本，失败时提示路径无效。
`settings.json` 保存 `kitsPath`、`builderPath`、`builderVersionInfo`、`builderStartupArguments`、`preferredTemplateId`，与现有界面设置一起原子写入，保留未知设置字段。

## 创建和编辑项目

创建页直接使用设置的共享模板目录，只展示依赖有效且数据版本兼容的模板。
支持模板头第三行的明确版本；有 `...` 的模板可手动输入能可靠排序的较新版本，最终由构建器给出警告。
版本比较兼容 `1.21.11` 到 `26.1` 的命名切换，不能可靠排序的快照必须明确列出。
`generatePath` 是父目录，最终数据包目录为 `generatePath/outputFolder`；未设置 `outputFolder` 或其为空字符串时使用项目名称。
总览构建栏可独立编辑生成文件夹名称，失去焦点或开始构建时自动保存。留空恢复使用项目名称。
“打开生成位置”打开当前配置的输出目录；尚未生成时打开父目录，不自动创建文件夹。自定义名称需要支持 `outputFolder` 的构建器。
创建项目不会覆盖同名目录，配置在四类元素目录创建完成后写入。
旧格式项目不能通过仅修改版本号使用新构建器，应另外创建新项目；不提供旧格式兼容接口。

## 进程和结果

`BuildManager` 是应用生命周期对象，启动时使用独立参数（不经过 shell）：

```text
builder/xcshop-builder-0.1.0.exe --project <项目目录> --kits <构建套件根目录>
```

它通过异步 `QProcess` 读取 UTF-8 stdout/stderr。只解析 stdout 中以 `XCSHOP_BUILD_RESULT ` 开头的完整行。
要求 `xcshop-builder/result` 协议版本 0；校验必要字段、错误和警告结构及数量。
结果必须包含 `mode`（`check` 或 `build`）和布尔值 `outputWritten`。`mode: "check"` 表示仅检查，成功时显示“检查通过 · 未生成数据包”；`outputWritten: false` 不显示“数据包已生成”，也不展示本次输出路径。缺少字段的结果作为协议错误处理。
普通日志、stderr、缺失/损坏/重复结果、非零退出码和进程崩溃不会被误报成成功。
错误保留文件、属性、原因、解决办法和 `terminatesBuild`，程序异常单独补充编辑器诊断。
控制台最多保留 256K 字符，单行上限 8MiB；没有百分比协议，所以界面不伪造构建进度。
切换页面不销毁进程或结果；结果按启动时的项目路径归属，不能同时启动多个构建。
构建期间不允许切换构建器、变更套件或修改商店注册。
取消先请求停止，2 秒后仍未退出则终止进程；取消后应重新构建确认输出。
退出编辑器时，若仍在构建会先询问。编辑器沿用现有自动保存，不增加“保存全部”步骤。

## 验证

默认不编译测试。配置 CMake 时启用 `-DXCSHOP_BUILD_TESTS=ON` 后：

```text
cmake --build <build> --target appxcshop editor_backend_tests builder_protocol_fixture
ctest --test-dir <build> --output-on-failure
```

后端测试使用临时目录和协议进程替身，不修改真实项目。
测试配置下 `appxcshop --ui-smoke` 会在临时目录执行创建、注册、真实 Alpha r0 构建、页面切换及项目设置检查。`--operations-ui-smoke` 验证操作与代价增删、标题和展示开关保存、两层展示预览及宽窄布局。
真实构建使用程序目录下的默认构建器和内置套件；不会写入 Minecraft 存档。
可用 `QT_QPA_PLATFORM=offscreen`、`QT_QUICK_BACKEND=software` 和 Windows 下的 `QT_QPA_FONTDIR=C:/Windows/Fonts` 运行离屏测试。
测试截图输出到程序目录 `ui-*.png`；正常编译不包含测试入口。

## Item 操作组继承与同条件唯一触发

Item 工作区的“操作组”标题右侧提供“继承自”开关和紧凑元素选择器，只能连接项目内的 Item。关闭开关或清除连接会将 `operationsFrom` 保存为空字符串；已有文件缺失此字段时也表示不继承。卡片仍只编辑当前 Item 自身的操作，继承内容保留引用，来源修改后下次构建即生效。

Item 元素管理器的文件右键菜单提供独立的“将操作组继承至…”入口，支持多选。弹窗复用完整版元素选择器，直接使用全局唯一的元素中转区，不创建弹窗内副本；弹窗期间临时提升该中转区至遮罩上方并预留空间，关闭后恢复原有层级与高度绑定；选择一个来源 Item 并确认后，全部选中文件的 `operationsFrom` 设置为该来源，保留各自的物品、展示和本地操作。取消不写入；弹窗未选择元素时不能确认。单个连接和批量应用都会拒绝自身继承、循环继承及失效来源。批量保存失败时报告未成功的文件数量；当前打开的元素成功写入后立即刷新。

构建时按“自身操作 → 来源操作 → 更上级来源操作”展开，不根据名称、执行内容或代价覆盖、合并重复操作。继承仅包含操作，不继承来源的物品或 Display；继承操作中的宏使用当前 UI 商品的宏参数。构建器检查全部继承引用，失效或循环连接定位到原 Item 的 `$.operationsFrom`，继承操作字段的错误仍定位到来源文件。

每张操作卡片新增“同条件唯一触发”，保存为布尔值 `uniqueTrigger`，默认 `false`。构建器在宏展开后按最终列表顺序处理：保留某个启用该选项的操作后，跳过后续触发条件完全相同的操作；不会回删前面的操作。比较的是 `trigger.mode` 的全部条件：拿取方式及其数量/栏位筛选，或掷出方式及单个/整组；名称、代价、执行内容、展示和提示开关不参与比较。隐藏操作同样可以阻止后续同条件操作。最终展示文本和执行列表使用同一个筛选结果。此开关在构建期生效，与游戏运行时的“成功后返回”独立；不向套件 IR 增加字段。

操作 UI 回归覆盖新开关的默认值和保存、宽窄标题布局、继承重开和清除、完整选择弹窗、全局中转区真实点击选择及关闭/取消后的恢复、Item 类型限制、多选批量应用、取消与循环检查。构建器独立的 `tests/operation-inheritance.mjs` 覆盖多级顺序、重复保留、宏替换、精确条件比较、展示一致性、非法字段、失效连接、循环和来源错误定位。
